# Controller postavy a pracovní cyklus

Person skládá skutečný FieldObject, PersonVisuals, PersonSounds, PersonTasks a ActionProcessor. Constructor0044f340 načte původní XML a profilovou pozici, vyhledá nesený sáček a instaluje idle. Destructor0044b3a0 nejprve zastaví hose, uvolní osm současných sound referencí, pak ostatní kanály; fronta a appearances zanikají před singletonem a FieldObject UI. ActionProcessor zaniká až po FieldObject. Moderní layout je oddělený od původních0x2b30 bajtů.

AbsoluteStep00449ad0 skutečně volá ButtonPrototype.enabledStep a potom ActionProcessor.step. Původní normální enabledStep je také ButtonPrototype.enabledStep; tento dvojí průchod se zachovává. Čekání00451760/0045a2c0/00451c30 aktualizuje UI nesených věcí, zpracuje cancel a z fronty vytvoří skutečný pěší nebo vozidlový pohyb. Dokončení pohybu volá dispatcher0045a730; vozidlové0045bbe0 přímo deleguje do stejného těla.

PersonActions.cpp obsahuje původní větve pro pole, sklad, Dig/Mow/WaterSource a SeedPackage. Časované akce odpovídají původním vtables005f3410–005f3490. Krok zachovává neuložený x87 rozdíl zbývajícího času a dokončí také unordered hodnotu. Field dokončení mění skutečné culture/FFS/fertility/water; sklizeň mění PCC a signed profilový store awGrowType, sklad používá skutečný Warehouse.give. Vybraný helper je source kód podle dekompilace a instrukcí, nikoli volání originálu.

Dosud přímo porovnaný controller: v PC53/PC24 celkem462 stavů,284 výslovných CPU operací a128 celých D3D8 snímků /61 440 000 přesně shodných RGB pixelů. Dvacet constructor/lifecycle scénářů v každé přesnosti zahrnuje carry0/1/2/6/11 a čtyři úrovně Dig/Mow. Ověřené je čekání, vodní a produktové UI, cancel bez současné značky, ownership a zánik. Sedm časovaných akcí skutečně vykoná převzetí nástrojů, kopání, sklizeň, zalévání a uložení produktů do skutečného skladu. Další akce probíhají automaticky v uvedených UI snímcích a nejsou přičítány k284 ručně vyvolaným operacím.

Vykreslený scénář používá celou postavu: skutečný Field mouse press/release vytvoří PersonTasks, ActionProcessor sám vybere vozidlový přesun, dispatcher spustí Dig, práce změní pole a nainstaluje idle. Test neřídí jednotlivé pohybové a pracovní kroky ručně. Značka se dokončí a odstraní přes skutečný deferred discard. Porovnávají se profily, UI, zvukové požadavky, action počty a resource teardown.

Farm je zatím skutečný StateView s FarmAreas, budovami, Field a HoseEmitter; kompletní Farm třída a cGame zbývají. Indikace pole a celkové Money/HUD refresh služby mají výslovné diagnostické hranice. Zvuk používá skutečný obnovený manager s vypnutým UI diagnostickým backendem; fyzický playback a vlastnictví kanálů ověřují samostatné PersonSounds/game-audio reporty. Přímé časy jsou řízené; render používá skutečný GameTimer. Původní kód se mapuje pouze v diagnostice.

Neověřené nové větve jsou výslovně další prací: carry10 při constructoru, sow/spotřeba/odložení sáčku, hose worker a skutečné emise, ostatní arrival větve, cancel se současnou značkou, opakované tutorial predikáty a dlouhá fronta pro award. Tutorial00451490 podle instrukcí skutečně kontroluje C14 místo C1c; C1c native constructor neinicializuje. Zdroj zachovává toto rozhraní a stav nevydává za ověřený. Výjimečné CRT ABI také zbývá.

Reprodukce: sestavit `text-buttons-reference-test`, spustit `python tools/validate_person_controller.py` nebo CTest `original-person-controller`. Výsledky a přesné hashe jsou v `analysis/person-controller-validation.json`. Úplné Win32 sestavení a88/88 CTest prošly za380.35 s; oba game-audio a PersonSounds buildy prošly aktuálními scénáři a striktní zápis ověřil source/binary hashe i17 nezměněných originálů. První úplný běh zachytil nechtěnou změnu kódování ruského testovacího řetězce; původní text byl obnoven a celý běh znovu prošel bez snížení kontrolních počtů. Regresi eviduje `analysis/person-controller-regression.json`. Celý původní cíl tím není splněný.
