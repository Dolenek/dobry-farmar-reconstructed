# Akční oblasti a návaznost skladu – probíhající rekonstrukce

Navazuje na ověřené Manufacture a FieldObject ([FIELD_OBJECT.md](FIELD_OBJECT.md)). `src/game/ui/ActionArea.h/.cpp` obnovují společný controller cActionArea a jsou zapojené do zdrojové knihovny. Warehouse, Farm a Person se dále rekonstruují; diagnostické world hranice nejsou jejich herní implementace.

`python tools/validate_action_area.py --build-dir build/windows` porovnává přímo původní instrukce a zdrojový controller v PC53/PC24: 86 objektů, 17 842 stavů, 14 784 parkovacích cílů, 2 208 kliknutí a 84 GPU snímků / 40 320 000 přesně shodných RGB pixelů. Používá sedm skutečných Farm/ActionAreas XML, šest area types, celou zdrojovou tooltip hierarchii a skutečný TutorialManager. Ověřuje tři reloady každého rootu, dalších deset částečných reloadů, clamp 4×12 parking offsets, append click offsets, uint přetečení čítače a pořadí callbacku vůči jeho změně. Fixture zaznamenává původní Farm registraci, cíle předané Person a výslovné dotazy na úrovně; nevytváří náhradní herní svět. Celý Farm/Person lifecycle, derived controllers, prázdný click list a význam neinicializovaného wordu +368 čekají.

`0041c010` constructor používá Field tooltip base `0041be20`, zapisuje area type `+364`, nuluje 48 parkovacích Point2 od `+36c`, vytváří overlay Picture `+500` a volá skutečnou Farm registraci `00431530`. Registrace jen appenduje pointer do Farm vectoru `+68/+6c/+70/+74`; nejde o domyšlené třídění. ActionArea destructor `004187a0` uvolní click-offset vector a přejde do tooltip destructoru `004182b0`. Sám neodregistruje oblast ani nemaže tasky postavy; tyto účinky nelze do destructoru přidat odhadem.

Native údaje: type `+364`, další word `+368` (constructor jej neinicializuje; helper `00417f60` vrací width a tento word), parking offsets `+36c` (4 × 12 Point2), click-offset vector allocator `+4ec`, begin `+4f0`, end `+4f4`, capacity `+4f8`, click index `+4fc`, overlay `+500`. Primary table `005ef958`, Field tooltip table `005ef7a0`; obě mají vlastní HeightOffset wrappers. Velikost a význam +368 pro všechny odvozené typy ještě vyžadují další ověření.

XML `0041cd10` nejprve načítá Field tooltip. Overlay přebírá skutečnou velikost a pozici, depth +0.001, původní default `FF202020` / případný OverlayColor, RenderType 9 a hide. ClickOffsetList appenduje další Offset records bez vyčištění. ParkingOffsets se naopak při každém load nuluje, pak bere nejvýše čtyři řádky a dvanáct offsets na řádek. Na konci vyvolá skutečné Field.setPosition nad aktuální pozicí.

`00418800` má skutečný ABI output Point2 a jeden index (RET 8), přes zavádějící debug string zmiňující další argumenty. Index 2 se upraví podle upgradu DigBuilding `0065f74c`, index 6 podle MowBuilding `0065f754`; oba if bloky jsou postupné. Typy 2/4/8/16 navíc přičítají dvanáctinásobek úrovně Warehouse/WaterSource/MowBuilding/DigBuilding. Výsledek je z vybraného parking offset plus aktuální position, s původními x87 operacemi. Nezávislé náhodné úrovně a pořadí dotazů odhalily původně chybnou záměnu typů 4 a 16; opravená implementace prošla oběma přesnostmi.

Click `00418c60` nejprve při active tutorial 44 nastaví cancel request (`004cdf10` zapisuje true, nikoli take/reset), potom skutečný Button.clicked, tipsDirection 1 a `00418110`. Tento helper používá postupně ClickOffsetList; po vyčerpání stále poslední offset, ale index dále zvyšuje. Nemá modulo ani fallback pro prázdný list. Potom vyvolá skutečný Person `0044d2f0`, který vytváří marker Picture a přidá action task. Potřebný Person/Farm provider musí obnovit tyto účinky; pouhé zaznamenání callbacku je jen diagnostika.

Warehouse singleton `0065f748`, constructor `00467fe0`: ActionArea type 2, další MI word `+504`, Upgrade `+508` (item type 12/property id 32), occupied count `+534`, čtyři 112bajtové levels od `+538`. Level constructor/destructor `00465f40/00465fa0` má capacity word, dvě 40bajtové appearances a String mask; numeric word constructor neinicializuje. UI pointers: LoadingSubstrain `+6f8`, Loading ProgressBar `+6fc`, UpgradeButton `+700`, CostText `+704`. Skutečné XML je `Farm/ActionAreas/Warehouse.xml`.

Goods `00467fa0` čte uint profile WGoodCount0..18; neplatný product vrátí 0. Free `00465e70` vrací current level capacity minus occupied s původním uint wrap. Give `00467ec0` a Take `004682d0` omezí transfer dostupným prostorem/zásobami. Při nenulovém transferu zachovávají pořadí: profile/count mutation → Warehouse progress `00466110` → Manufacture labels `004953e0` → HUD warehouse `004beb40` → volitelně obchodní scéna `0046f9e0` (singleton `0065ffc8`) → HUD stock/contract notifications `004bd9d0` → WareDetail tooltip `00464b40` (singleton `0065ffc4`, constructor `004658b0`, XML `UI/gameUI/WareDetail.xml`). Poslední příjemce není Warehouse; potvrzuje jej ECX těsně před call. Give opakuje profile lookup při zápisu; Take nejprve sníží occupied, potom zapíše profile. Flag argumenty a nulové transfery se musí ověřit přímo. Součet nákladů `00466a40` zahrnuje indexy 1 až level−1, nikoli aktuální level.

Další potřebné bodies: Warehouse XML `00467220`, Upgrade refresh `00466530` (ECX ukazuje na Upgrade subobject), clicked `00466e30`, hovered `00448b20`, cargo animation, upgrade cost/callback/destruction a celý WareDetail. Warehouse clicked zkouší Farm gates `0042d700(0)` a `0042db30(0)`; jejich výsledky rozhodnou mezi ActionArea.clicked a obyčejným Button.clicked. Plný svět, tutorial, saves a herní EXE zůstávají nedokončené.
