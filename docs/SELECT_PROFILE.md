# Výběr profilu

`SelectProfile` obnovuje původní singleton (196 bajtů, MenuView subobject +4): konstruktor `004fffb0`, default XML `004fca60`, loader `004fcea0`, seznam `004fefa0`, step `004fe070`, enable/disable `004fdfd0`/`004fe020`, destructor `004fe870`, výběr řádku `004feaa0`, accept/cancel `004fd780`/`004fdbb0` a mazání `004ffb70`, `004ff410`, `004ffa00`. Callback změny jména je neindexovaný rozsah `004fe9b0..004fea9b`; konstruktor má doložené pokračování přes `005002e3`, které exportovaný rozsah instrukcí nezahrnuje. Zdroj používá moderní objektovou hierarchii a vlastní upravitelné implementace; původní PE slouží výhradně diagnostice.

Pořadí vlastněných controls odpovídá instrukcím: OK/Exit/Delete TextAnimationButton, EditBox, tři Picture, EnterName TextLine, ListBox. Skutečný ResourceManager načítá `UI/SelectUser.xml`; MenuView přidá Background dekoraci a vlastní samostatný Background Picture načítá celý sekční uzel. Loader zachovává StringOK/New/Confirm, hideCancel a počáteční skrytí Delete. Seznam se obnovuje z UTF-16 řazených hlaviček aktivního profilu.

Prázdné jméno v changed callbacku skrývá OK; Delete zde nemění. Neprázdné jméno ukáže OK, shoda s aktivním řádkem nastaví StringOK a ukáže Delete, jinak StringNew a skryje Delete. Step zapíná/vypíná OK podle prázdného jména. Confirm propustí Backspace nebo znak dostupný ve fontu (`004db9f0` → `0050b3d0`). Enter přijme neprázdné jméno; Escape funguje pouze s neprázdným seznamem a skutečně viditelným/zapnutým Exit. Výběr řádku přepne profil ihned. Destructor vždy odstraní vlastní klávesové bindings, bez ohledu na stav enabled.

`ProfileSession` vlastní Profile singleton a při přepnutí provede obnovený destructor/persistenci a nový constructor s 790 skutečnými herními defaulty, ResourceManager XML cache a invalidací. Accepted/Cancelled callbacks nemají argumenty. Mazání vypne/skryje výběr a vytvoří skutečný YesNo root, který dostane StringConfirm. No zařadí dialog do odloženého odstranění a obnoví selector. Yes odstraní jméno, obnoví seznam, skryje Delete, vyprázdní editaci a **skryje Exit** podle původních instrukcí; následně otevře první zbývající profil. Diagnostické původy jsou `.\Ui\SelectProfile.cpp400` a `410`. Při odstranění souborů zůstává původní vyloučení přípony pack.

`analysis/text-buttons-validation.json` eviduje obě x87/device přesnosti: 32 vlastněných selectorů, 1 650 stavů, 72 256 úplných letter/sprite porovnání, 40 accept/cancel callbacků, 24 potvrzených mazání a 360 událostí nativní profilové služby. Testuje prázdný/jeden/tři skutečné profily, hideCancel, RTL, znakové potvrzení, výběr řádků, přepínání, Enter/Escape, Yes/No a úplné input/resource uvolnění. Source skutečně zapisuje hlavičky/vlastnosti, po close ověřuje CurrentUser/NowPlaying a odstranění XML/sav/sav.bak; No tyto soubory ponechá a pack zůstává v obou případech.

Celých 64 GPU snímků selectoru a jeho modal dialogu porovnává 30 720 000 RGB pixelů a draw API volání beze změn. Zdroj používá obnovené View/Control registry, EditBox s caret, ListBox, textové buttons, časovač, cursor a batching. Native profily mají explicitní 88-byte service fixture pro open/close/name-list/remove; source používá skutečnou persistenci, samostatně ověřenou proti nativnímu lifecycle. Proto tato kontrola není porovnáním celého nativního profile+UI runtime. XML adapter používá nezávislý strom ze skutečných dat; frame/input/clock/graphics/audio hranice jsou stejné jako u diagnostiky hlavního menu a YesNo. Zvukové požadavky se porovnávají, audio se nepřehrává.

Zbývá startup/navigace hlavního menu, fyzický vstup, skutečné audio a herní runtime, společné nativní profile+controller ověření, úplné původní object/exception ABI. Scrolled ListBox clear nadále vyvolá zdokumentovanou bezpečnou source výjimku namísto původního přístupu do uvolněné paměti. Neplatné XML/font/rozměrové vstupy nebyly celé porovnány.
