# Zvuky a kanály postavy

Navazuje na3d1525a s pěším/vozidlovým pohybem a85/85 CTest. PersonSounds obnovuje0044a820,0044ad50 a čtyři stop metody00449820/40/60/80. Používá skutečný SoundManager a cChannel s vlastní sestavenou Squall DLL; původní binární kód se v implementaci nevolá.

Pole osmi resources poskytuje PersonVisuals/actor: shovel,tractor,watering can,seeding,scythe,well,hose,warehouse. Helper vlastní pět cChannel wrappers. Kinds0/1/2/4 vždy nejprve zruší starý kanál, pak přehraje novou smyčku se start=true. Kinds3/5/7 jsou podmíněné jednorázové kliky. Hose6 vytvoří kanál pouze pokud chybí a existuje resource, se start=false; následně vždy volá start existujícího wrapperu. Cached hose se tak obnoví i při právě prázdném resource slotu. Generický stop0044ad50 má tělo jen pro6. Vodu/scythe/shovel/tractor ukončují čtyři samostatné původní metody.

Helper neownuje osm resource referencí. Destructor ukončí hose a potom watering/scythe/tractor/shovel. Úplný actor musí ještě zapojit původní pořadí sound-ref releases mezi hose a zbylé kanály spolu s appearance/UI/action destrukcí; tato část Person lifecycle tím není vykázaná jako hotová.

Samostatný person-sounds-reference-test mapuje původní EXE jen jako oracle konkrétních šesti sound metod. Native data adapter má pouze potřebná sound/channel pole. SoundManager boundary používá skutečný obnovený manager, cSound a16-byte cChannel; cChannel.start boundary je již samostatně native-porovnaná source implementace. Zdrojový i původní controller běží na stejné fyzické DLL v každém scénáři, nejdřív vlastní a potom původní DLL. Číselná channel ID se párují, nepředpokládá se jejich rovnost.

PC53/PC24 na obou DLL:332 stavů /328 akcí /616 přesně porovnaných API událostí,40 kontrol skutečného postupu smyček a8 kontrol nehybné paused pozice. Skutečné XML resources, source callbacky, loop/start/group/frequency/pan/volume parametry, replay pořadí, reference deltas, cached hose resume při null resource, výměna resource za běhu, unsupported kinds, opakované stop a helper teardown jsou porovnané. Hlasitost je0; audible shoda a průběžná refill PCM tím ověřené nejsou. Samotná shoda controllerů na každém backendu není důkaz celé Squall implementace.

Diagnostika současně provozuje deset smyček dvou porovnávaných controllerů. Původní i sestavená DLL při příliš rychlém replay přes16 obsazených slotů přebírají jiný kanál. Zastavený, dosud neuvolněný kanál se neprojeví jen v počtu Play/Pause; test proto čeká na konkrétní zastavená ID, až API vrátí NONE. Do hry se kvůli tomu nezavádí žádný sleep ani omezení. Caller x87 kontext se vybírá po načtení DLL/CRT, stejně jako ve starším game-audio oraclu; starý CRT startup může při LoadLibrary změnit FPU nastavení.

Reprodukce: cmake --build build/windows --config Release --target person-sounds-reference-test a python tools/validate_person_sounds.py. Target vyžaduje BUILD_SQUALL_CANDIDATE=ON a kopíruje pouze vlastní source DLL. Úplná86-test regrese prošla za386.41 s; samostatné sestavení prošlo stejnými scénáři a striktní zápis ověřil source/binary hashe i17 původních souborů. Full Person actions/Farm/EXE, obousměrné saves, zbývající97-export chování Squall a izolovaný odinstalátor pokračují.
