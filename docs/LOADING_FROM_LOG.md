# LoadingFromLog

Zdrojová obrazovka `src/game/ui/LoadingFromLog.cpp` obnovuje konstruktor `00480770`, XML `00480110`, krok `00481130` a destruktor `0047fff0`. `ResourceManager::loadFromLog` obnovuje skutečný dispatcher `00541700`: Type 0 textura, 1 XML s deleting destructor, 2 font, 3 shader, 4 zvuk. Ostatní hodnoty originál ignoruje. Každé načtení ostatních typů uvolní právě získanou referenci; cache prostředek ponechá pro následné použití. Chybějící Type zachová předchozí hodnotu, zpočátku první index dávky, podle opětovně použitého původního stack slotu.

Obrazovka vytvoří samostatný ProgressBar bez rodiče a dekorace ze skutečného `UI/Load.xml`. `MusicPlayback` představuje sdílené původní pointery `0065ffdc/0065ffe0`: nejprve smaže starý kanál, pak uvolní prostředek, získá zvolenou hudbu a spustí ji přes skutečný SoundManager s loop/start=1. Volume atribut v XML zde originál nepoužívá. Stav hudby přežije zničení obrazovky; aplikace jej musí vyčistit před SoundManagerem.

První krok volá clearUseless právě jednou. Globální maximum progressu `0065ffe4` se inicializuje z prvního aktivního ProgressBaru a sdílí mezi dalšími obrazovkami. Konec dávky používá původní 32bitový součet a unsigned minimum. Hodnota progressu používá **počáteční** index dávky, násobený sdíleným maximem a dělený celkovým počtem; při dokončení se proto automaticky nenastaví 100 %. Dokončení nejprve zavolá callback, pak skryje obrazovku a vloží ji do odloženého mazání s původním origin stringem. ProgressBar i XML se uvolní při pozdější destrukci.

Chybějící log originál řeší voláním callbacku a smazáním objektu přímo v konstruktoru. Moderní factory zachovává pořadí událostí a destrukci před návratem, ale vrací nullptr namísto již uvolněného pointeru. Moderní objektové a exception ABI tím není označené za původní.

`python tools/validate_loading.py` provádí skutečné původní instrukce, entry point EXE nespouští. Používá skutečné logy `GameResLog.xml` (539 položek: 431 textur, 60 XML, 45 zvuků a 3 fonty) a `MenuResLog.xml` (148 položek: 125 textur, 14 XML, 6 zvuků a 3 fonty). PC53/PC24: 902 stavů, 864 dávek, 14 vlastněných existujících obrazovek a 2 missing-log větve. Dávky 1/3/7/30/UINT_MAX, zero-batch, sdílené maximum, callbacky a skutečná native discard mapa jsou porovnané. 24 D3D8 snímků má všech 11 520 000 RGB pixelů i draw volání totožných. XML deleting boundary zde počítá volání přes nezávisle vlastněné immutable stromy; cache identita a chybové větve zůstávají výslovnou hranicí fixture. Zvuk je v tomto UI oracle záměrně disabled.

`python tools/validate_game_audio.py` navazuje skutečným produkčním audio backendem. Obě DLL normálně načítá výhradně diagnostika, produkce importuje vlastní Squall.dll. Na obou přehrávajících backendech projde zdrojový LoadingFromLog celé oba skutečné logy, načte skutečné GPU/font/XML/sound prostředky, vymění hudbu, pozastaví a obnoví fyzický playback, dokončí a smaže kontrolní stromy. Celý rozšířený scénář v PC53/PC24 porovnává 378 stavů, 36 postupů playback cursoru a 16 frozen pause kontrol; hlasitost je při playback kontrolách nula. Časové přírůstky se nezaměňují za přesnou shodu plánování. Stejný scénář se ověřuje také v samostatném sestavení.

Portable výsledky jsou v `analysis/loading-validation.json` a `analysis/game-audio*-validation.json`. Callback ve všech těchto diagnostikách **počítá dokončení**, nepředstírá implementaci `cGame`. Hlavní menu ještě potřebuje původní navigační controller a skutečný herní svět. Type 3 není v dodaných logách, malformed/missing Type, prázdný log/NaN a extrémní indexy i exception ABI zůstávají neověřené. Celá hra a save kompatibilita stále nejsou dokončené.
